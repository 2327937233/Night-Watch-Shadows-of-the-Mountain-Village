# 《守夜：山村旧影》视觉审查 · 第一阶段

审查日期：2026-09-08。范围：现有庭院、祭祀厢房、门外与共享 HUD。这里只记录现状及下一步标准，不把审查文档当成已经完成的美术优化。

## 检查方法与边界

- 使用 Godot 4.7.1、Forward+、RTX 5060 实际加载项目，保留游戏镜头跟随、角色和 HUD；入口截图使用场景初始位置，门前及供桌截图仅在独立测试进程移动角色以检查近景。
- 未调整曝光、环境光、场景资源、角色控制、任务或背包逻辑。没有使用参考图片替代游戏建筑。
- 截图入口：`tmp/art_audit_capture.gd`。渲染输出：`tmp/art_audit_*.png`。日志：`tmp/art_audit_stdout.txt`、`tmp/art_audit_stderr.txt`。
- 节点统计不等于 draw calls、可见灯数或帧率。当前还没有完成目标硬件的连续游玩、GPU 帧耗时与显存测试。
- 启动受限进程曾在日志初始化失败后崩溃；允许本地渲染并指定项目内日志路径后成功。退出日志有 Texture RID 泄漏警告，需要单独跟踪，不应宣称零警告。

## 当前最大的十个视觉问题

| 排序 | 问题与实测证据 | 原因/修复方向 | 验收方式 |
| --- | --- | --- | --- |
| 1 | 庭院右侧、室内两壁与顶梁大片融成黑色；入口处无法读出侧墙层次。见 courtyard_entry / ritual_entry。 | 区分材质过暗、几何遮挡和光线不足；共享建筑 shader 的湿度、污迹、墙根与裂纹连续乘暗，先校准材质与 UV，再调有来源的局部反射光。禁止全场提曝光。 | 手电关闭仍见墙柱大轮廓；打开后出现粗糙度与细节，角落仍暗。 |
| 2 | 主门位置正确，但远景被近处左灯笼抢焦点。近景门扇、台阶仍是大块均匀色面。 | 已有实体，不需退回贴图或推翻地图；补边缘磨损、门板接缝与包边体积；控制近灯发光，强调门洞两侧及石阶边缘。 | 入口正常镜头下，主门是远端明确目标；斜角可读门洞进深与台阶厚度。 |
| 3 | 祭祀供桌、香炉、供果和牌位有明显基本几何体感；缺少近距离叙事细节。 | 目前大量单色 Box/Cylinder；仅名称并不代表蜡泪、刻字或榫接已经建成。保留位置，用中等形体与少量边缘几何替换；不要盲目加雕花。 | 近景可分辨木、铜、陶、纸；牌位层级与文字不靠自发光获得。 |
| 4 | 室内地砖像黑色规则棋盘，砖缝宽、整齐、材质均匀。庭院虽已有 PBR，长距离仍有重复感。 | 室内逐砖 110 个节点使用单色材质；庭院已有多张材质贴图，不应重造。后续独立处理尺度、粗糙/湿润/积水分区、接缝、变体和批处理。 | 同镜头对比；室内不再像新铺格子；庭院不变镜子，也不增加每砖独立节点。 |
| 5 | 木柱和墙面局部高光像亮漆；祭台侧墙污迹呈横向条带，重复和拉伸明显。 | 很长的盒体共用 UV_repeat，纹理物理尺度不统一；材质种类的湿度响应未充分分开。建立按材质、部位控制的 UV 与 wetness，墙根变深而非整墙抹黑。 | 手电横扫墙与柱，高光宽度明显不同；墙面是块状霉斑加竖向渗水，不是等距条纹。 |
| 6 | 灯笼虽有框，但灯纸依然是过于均匀的亮色矩形，框纸比例与近远观感不一致。 | 统一有支架的方灯模块，四面均有结构，朝院一面可见木格；纸面旧化与光源分离。 | 近景见纸、框厚度和吊挂，远景只留克制暖点；不得悬浮。 |
| 7 | 屋顶/檐下形成大片硬黑轮廓，主门屋顶远景像平直条板。 | 层次集中在局部，整体瓦面轮廓与梁椽受光不足；保留建筑尺度，补分层轮廓、瓦沟、檐底接头，避免仅堆小瓦片节点。 | 中轴与左右斜角均可辨屋檐、梁、瓦面；不增加无理由装饰。 |
| 8 | 香烟明显是白灰矩形串，尘埃是小方片；蜡烛火焰是亮圆柱。 | 烟尘 QuadMesh 没有柔边密度贴图/遮罩；火焰直接用 cylinder。改低成本软遮罩、随生命周期淡入淡出和微摆动，核心蜡烛才投影。 | 香烟细慢且在烛光处隐约可见，无方片；火焰有灯芯/蜡体关系，不是黄色棒。 |
| 9 | 角色清晰度、亮度与房间不一致；供桌暖光附近仍显冷亮，脚下接触感偏弱。 | 两个 3D 场景均设置 AnimatedSprite3D.shaded=false；手电为固定局部偏移，不是逐帧灯头标定。不要直接切换 shaded 后宣称完成；先做独立视觉层试验，处理贴图自带光与环境色。 | 原地转向、步行、台阶、靠灯、背光五组对比；无白边和脚漂，手电跟右手。 |
| 10 | UI 基础字体/色系可保留，但图标风格不完全一致，背包尚非要求的三栏调查页；门外与 3D 庭院还存在呈现方式断层。 | 门外场景是 Node2D + TextureRect，不是完整 3D。不能冒充已整体改成 3D；先统一转场、色彩和 HUD。背包按分类/网格/详情扩展，保留逻辑接口。 | 同分辨率跨场景对比；Tab 打开，ESC 优先关闭面板，关键物品可读且不挡掉游戏背景。 |

## 已有成果，应当保留

- 庭院中轴开敞，左右形成包围，主门位于尽头；祭祀室入口到供桌的纵深关系成立。
- 庭院石材已有 albedo / normal / roughness / AO / height / wetness / puddle / moss 贴图，不是所有材质都要重做。
- 庭院雨已有远、中、近三层；祭祀室没有创建雨粒子。后续应检查贴近屋檐时雨域跟随玩家造成的穿屋风险，而不是重复增加三套雨。
- 门框、门扇、台阶、梁柱已有几何，问题是完成度与受光，不是用新背景图覆盖。
- HUD 的中文字体、暗金方向及 F/Tab/ESC 位置符合整体方向，可渐进式完善。

## 单独记录的功能缺口

1. `courtyard_3d.gd` 主门 E 分支仍直接切入主屋，没有检查 `GameState` 钥匙。已有钥匙与背包代码不等于闭环完成。
2. `game_state.gd` 仅内存字典，跨场景保留不等于退出游戏后保存；是否接存档需明确设计，不应静默宣称永久保存。
3. 家谱当前主要为场景展示，物品特写仍待实现；背包物品定义目前仅钥匙。
4. 本次只验证场景加载与渲染，不声称已覆盖全部碰撞、拾取、门锁和暂停输入回归。
